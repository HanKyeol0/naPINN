# Cylinder-PIV four-Gaussian Korean report build notes

- Audience: technical.
- Delivery mode: repository-native Markdown generated by
  `analysis/build_legacy4g_rebuttal_report_ko.py`.
- Decision supported: whether and how to release the completed direct
  legacy-4G Cylinder-PIV results during rebuttal.
- Primary comparison: the predeclared `(b,o)=(1,1)` setting that preserves

## Required-structure mapping

- Technical summary: `technical_summary`.

  setting and fresh-seed candidate sections.
- Scope, data, and definitions: `scope_definition` and `severity_note`.
- Experimental design: `methodology`.
- Limitations and robustness: `limitations` plus per-seed tables.
- Recommended next steps: `strategy` and `next_steps`.
- Further questions: the numbered author decisions in `next_steps`.

## Quantitative evidence map

1. `chart_exact_rmae`
   - Question: how all eight methods compare at the two mandatory outlier
     ratios under the predefined reference corruption scale `(b,o)=(1,1)`.
   - Form: compact Markdown comparison table.
   - Dataset: 16 method-by-ratio aggregate rows.
   - Claim: naPINN-MSE has the lowest rMAE at both ratios under that
     predefined reference setting.
2. `chart_candidate_gains`
   - Question: which selected scale candidates generalized to fresh seeds.
   - Form: signed Markdown comparison table.
   - Dataset: three candidates by two field metrics.
   - Claim: two candidates pass the frozen mean definition, but the third
     has adverse rMAE.

Per-seed results use a table rather than a chart because there are only three
reporting seeds per candidate and exact paired lookup is the analytical job.
Detection and physics metrics use the exact table because their differing
units would make a combined chart misleading. The prior HTML chart
definitions were replaced with exact-value Markdown tables at the user's
request that all report documents use Markdown.

## Transformations

- Means and sample standard deviations are read directly from the complete-only
  aggregations.
- Relative gain is `(baseline - naPINN) / baseline * 100`.
- The strongest non-naPINN method is selected separately for rMAE and rMSE;
  the same method happens to be strongest for both metrics in every reported
  cell.
- Severity ranges are read from the sealed artifact metadata across seeds
  40--42.
- No seed-39 metric enters reporting tables.
- Reader-facing prose explains the internally used labels `legacy`,
  `exact center`, `transfer`, and `synthetic core` in ordinary language
  before relying on them. It also defines held-out PIV, rMAE/rMSE, PDE
  residual, AUROC, gate, baseline, and paired comparison.
- Widget datasets are round-tripped through an in-memory SQLite table by the
  builder before Markdown rendering. Raw JSON/YAML/Markdown inputs remain
  cited beside the relevant narrative and tables.
